**Goal**：完成 P4 段 L。使用者可以在預算頁對浮動支出主分類設定**預設值**與**某個歸屬月份的覆寫值**，看到每個主分類的預算、實際、剩餘與使用率；總覽頁加一張預算摘要卡。J 段的「改支出性質」與「刪除分類」補上預算檢查，備份升到 v4。

**Architecture**：新 aggregate `CategoryBudget`（獨立於 `Book`，spec §5.1），主鍵就是 `CategoryId`（Q6），覆寫值是 owned collection（D1）。「哪些分類要列出、預算取預設還是覆寫、子分類併入主分類、剩餘怎麼算」放在 Domain 的純函式 `BudgetSheet`；實際支出由 `ILedgerSummaryQuery` 新增的一條 SQL 彙總（依分類加總該月的支出交易，含電子錢包消費，ADR 0008）。Application 負責查資料、呼叫 `BudgetSheet`、寫稽核與存檔。前端新增 `features/budgets`，依月份切換、行內編輯，總覽頁另外呼叫 `/budgets` 組摘要卡。

**Tech Stack**：.NET 10、EF Core 10（Npgsql）、MediatR、FluentValidation、xUnit v3、FluentAssertions；Angular 22.2、Angular Material／CDK 22.2、Vitest、Playwright。

### 本計畫做的決定

Q1–Q8 由使用者於 2026-10-09 grilling 確認；D1–D6 由使用者於 2026-10-09 確認（D6 是總覽卡的算法）。

| # | 決定 | 理由 | 被否決的選項 |
|---|---|---|---|
| Q1a | 只有覆寫值、沒有預設值的分類，其他月份回 `budget: null`、`source: null`（畫面「未設」），actual 照常列出，不算剩餘 | spec §5.2 每個浮動主分類都列出 | 沿用最近一次的覆寫值 |
| Q1b | 刪除預設值時**保留**覆寫值 | 每筆覆寫值都是對某月的明確決定 | 一併清除 |
| Q1c | 預設值與所有覆寫值都清空時，**整筆刪除** `CategoryBudget` | 「有這筆資料」＝「有預算紀錄」，`ChangeExpenseNature` 的擋法和畫面一致 | 保留空殼 |
| Q1d | 預設值、覆寫值都 `>= 0` | 覆寫成 0 可以表示「這個月不花這一類」 | 必須 > 0 |
| Q2 | 預算寫入**不檢查鎖帳日** | 預算不產生分錄、不影響餘額；預設值跨月份，只擋覆寫值會讓規則不一致；與 K 的週期項目相同 | 覆寫值依歸屬月份最後一天檢查 |
| Q3 | **不做**樂觀並行，後寫蓋先寫 | 每次寫入只設單一格、冪等；行內編輯不必處理 409 | 比照 K D9 用 xmin |
| Q3 附註 | 同時建立第一筆預算撞主鍵回 500，沿用現狀 | 與 issue #2 同一類 | 在 L 對應成 409 |
| Q4 | 備份升到 **v4**，加入 `Budgets`；還原接受 v1–v4；經 Domain 重建並比對一致性 | 不備份則還原後預算消失 | 不備份 |
| Q5 | issue #1（month key 年份範圍）**L 不處理**，沿用現有 validator | #1 單獨修時所有 endpoint 一次改齊 | 只在 L 修 |
| Q6 | 稽核 `AuditEntityTypes.CategoryBudget`；entity id ＝ `CategoryId`，`CategoryBudget` 的主鍵也是 `CategoryId`；不新增 `CategoryBudgetId` | Q1c 刪除後會重建，自有 Id 會把同一分類的稽核歷史拆散；主鍵直接擋住「一分類最多一筆」 | 自有 Guid v7＋唯一索引 |
| Q7 | 快照 ＝ 整個 aggregate：`CategoryBudgetDto(CategoryId, DefaultAmount?, Overrides[{ budgetMonth, amount }])`，覆寫值依月份排序、不帶 version；與備份 v4 共用 | ADR 0006 完整快照 | 只存被改的那一格 |
| Q8a | 第一筆值 → `Create`（before null）；刪到全空 → `Delete`（after null）；其餘 `Update` | 與 aggregate 生命週期一致 | 一律 `Update` |
| Q8b | PUT 同值**照樣寫稽核** | 守住「每個寫入 endpoint 恰好一筆記錄」 | 比照 K D8 不寫 |
| Q8c | DELETE 不存在的預設值或覆寫值 → **404** | 與其他資源一致 | 冪等 204 |
| D1 | 覆寫值存成 owned collection（資料表 `CategoryBudgetOverrides`，鍵 `(CategoryId, BudgetMonth)`），不用 jsonb | Q3 不做並行控制：jsonb 整欄覆寫，兩台裝置同時改**不同月份**會無聲遺失其中一筆；owned 表各月份各一列，互不覆蓋 | jsonb 欄位（對應簡單，但有上述遺失問題） |
| D2 | `CategoryBudget` 對分類**沒有 FK**（另有 `BookId` 欄位與索引），參照完整性由 `SettingReferences` 擋 | 分類是 `Book` 的 owned entity，EF 不允許其他 aggregate 以 FK 指向 owned type；與週期項目相同（K8） | 改分類對應方式（範圍過大） |
| D3 | actual 由 `ILedgerSummaryQuery.ExpenseTotalsByCategoryAsync(bookId, month)` 在 SQL 端依 `CategoryId` 加總 `Kind == Expense` 的交易（不排除電子錢包帳戶），子分類併入主分類由 Domain `BudgetSheet` 做 | ADR 0008；M 段的月報也需要「依分類的支出合計」，放在同一個彙總介面可以重用 | 在 Application 載入整月交易後用 LINQ to Objects 加總（多一次往返＋把資料拉回來） |
| D4 | 寫入已封存分類的預算**不擋** | 與 J D7／K D7 一致：後端不以封存為驗證條件，前端選項排除即可 | 擋下 |
| D5 | `PUT .../default`、`PUT .../overrides/{budgetMonth}` 的 body 是 `{ amount }`，回傳 200＋`CategoryBudgetDto`；DELETE 回 204（含刪到整筆消失的情況） | 前端行內編輯後以回傳值更新該列；不必再查一次 | 回 204，前端重新 GET |
| D6 | `GET /budgets` 回傳 `{ rows: [...], totals: { budget, actual, remaining } }`，**與 spec §5.2 的「每列一筆」形狀不同**：多包一層 totals。totals 只加總**有設預算**（`budget != null`）的列：budget＝預算加總、actual＝同一批列的 actual 加總、remaining＝budget − actual。總覽卡直接顯示 totals | 沒設預算的分類沒有上限，算進已用會把剩餘拉低；由後端回傳 totals，規則不必在 TS 再寫一份（Q11 的精神） | 已用＝所有浮動主分類的 actual；前端自行加總 |
