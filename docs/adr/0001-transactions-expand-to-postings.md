# 交易展開為分錄，而非單式記帳列

Excel 版是單式記帳：一列帶正負號的金額，由「方式＋主選單＋副選單」隱含決定動到哪些帳戶。Web 版改為「交易 → 一或多筆分錄」：使用者輸入介面維持 Excel 的手感，但存檔時依交易類型展開成分錄，帳戶餘額即分錄加總。選擇這個做法，是因為轉帳、提款、加值、繳卡費、新增貸款、貸款繳款、財務規劃帳戶進出都是跨帳戶的移動，資產負債表、尚待繳清與剩餘本金也都只是帳戶餘額。單式做法會讓「這筆動到哪些帳戶」的規則散落在每個報表查詢裡。

## Consequences

- 匯入 xlsm 時需要一層轉換，把 Excel 的隱含規則寫成明確的展開規則；這層轉換本身就是規則的測試案例。
- 交易類型（系統定義、決定分錄）與分類（使用者自訂、只供報表）是兩個獨立概念，Excel 的「副選單」被拆成分類或對方帳戶。
