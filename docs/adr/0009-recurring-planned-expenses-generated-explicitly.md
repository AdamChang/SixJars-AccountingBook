# 週期預定支出由使用者明確產生，同一來源同一月只產生一次

週期預定支出不會自動變成某個月的預定支出：使用者在預定支出頁對某個歸屬月份執行「產生」，系統才依週期項目建立該月的預定支出，並在預定支出上記錄來源週期項目，`(來源, 歸屬月份)` 唯一。唯一性**包含已軟刪除的預定支出**：使用者刪掉某月產生出來的一筆，再按一次「產生」也不會讓它回來。理由是未付的預定支出會扣減月可用餘額，任何時機不明的寫入都會讓總覽頁的數字無故變動；而刪除代表使用者已經決定「這個月沒有這筆」，重新產生會推翻這個決定。

## Considered Options

- **第一次讀取某月時自動產生**：GET 帶寫入副作用；只是瀏覽未來月份就會建立資料並改變那些月份的月可用餘額。
- **排程在每月 1 日產生**：需要 Cloud Scheduler 這個額外的部署元件（ADR 0007 之後已經不需要排程），而且使用者無法掌握產生的時點。
- **唯一性不含已刪除的資料**：刪除後再按「產生」會讓刪掉的項目復活，「產生」就不再冪等。

## Consequences

- 想讓已刪除的那筆回來，只能手動新增預定支出（來源為空），不是重新產生。
- 修改週期項目不會自動回寫已產生的預定支出；另外提供一個同樣是明確動作的「以現值更新」，只更新該月未付、且由週期項目產生的預定支出。
- 週期項目一旦產生過預定支出就不能刪除，只能設定結束月份，否則來源參照會斷掉。
